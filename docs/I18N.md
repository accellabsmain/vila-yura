# I18N.md — Internationalization Architecture

> **Depends on:** `ARCHITECTURE.md` (routing), `SEO.md` (hreflang)
> **Feeds into:** `CONTENT.md`, `COMPONENTS.md` (LanguageSwitcher)

---

## 1. Locale Strategy

Dua locale, prefix-based, fully localized URL (keputusan sudah dikunci di `ARCHITECTURE.md`):

```text
/en/...
/id/...
```

Tidak ada default-locale-tanpa-prefix. `/` redirect ke locale hasil deteksi (`Accept-Language` header) atau fallback ke `en`.

---

## 2. Slug Mapping

Slug **fully localized per locale**, bukan shared:

```ts
slug: {
  en: "hilltop-villa",
  id: "villa-bukit"
}
```

Ini menghasilkan:

```text
/en/villas/hilltop-villa
/id/villa/villa-bukit
```

**Rule:** setiap entity baru di `data/villas/*`, `data/experiences.ts`, dan journal article wajib punya slug EN dan ID sejak dibuat — tidak boleh partial (hanya EN lalu ID menyusul).

---

## 3. Path Segment Localization

Bukan cuma slug — segment path-nya sendiri berbeda:

```text
EN: /en/villas/...
ID: /id/villa/...     (singular, sesuai konvensi Bahasa Indonesia)
```

Mapping segment disimpan di `lib/constants.ts`:

```ts
export const PATH_SEGMENTS = {
  villas: { en: "villas", id: "villa" },
  experiences: { en: "experiences", id: "pengalaman" },
  journal: { en: "journal", id: "jurnal" },
} as const;
```

`ARCHITECTURE.md` folder structure (`app/[locale]/villas/`) tetap satu folder — locale-specific path segment di-resolve lewat routing config, bukan duplikasi folder per locale.

---

## 4. Translation File Structure

```text
messages/
├── en.json
└── id.json
```

Key terstruktur per section, bukan flat:

```json
{
  "nav": { "villas": "Villas", "about": "About" },
  "hero": { "cta": "Explore Villas" },
  "footer": { "copyright": "..." }
}
```

**Rule:** setiap key baru di `en.json` wajib punya pasangan di `id.json` di commit yang sama. CI check (opsional, lihat `IMPLEMENTATION.md`) bisa validasi key parity.

---

## 5. Content vs UI String

Dua sumber teks yang **tidak boleh tercampur**:

| Jenis | Lokasi |
|---|---|
| UI string (nav, button label, footer) | `messages/{locale}.json` |
| Entity content (villa name, description) | `data/villas/*.ts` (field bilingual object) |

Komponen tidak boleh punya string hardcode dalam bahasa apapun.

---

## 6. LanguageSwitcher Behavior

- Client Component (lihat `ARCHITECTURE.md` section 4 & `PERFORMANCE.md` section 5)
- Switch locale mempertahankan halaman yang sama, dengan slug yang di-resolve ke pasangan locale-nya (via `slug.en` ↔ `slug.id` mapping di data layer) — bukan redirect ke homepage locale lain.

```text
User di /en/villas/hilltop-villa → switch ID → /id/villa/villa-bukit
(bukan /id)
```

---

## 7. hreflang Enforcement

Setiap page wajib emit `alternates.languages` (detail implementasi ada di `SEO.md` section 2 & 4). Ini bukan opsional — tanpa ini, dua locale akan dianggap duplicate content oleh search engine.

---

## 8. Date, Currency, Number Formatting

```ts
// Gunakan Intl API, bukan hardcode format
new Intl.DateTimeFormat(locale, { dateStyle: "long" }).format(date);
new Intl.NumberFormat(locale, { style: "currency", currency: "IDR" }).format(price);
```

Currency default: IDR untuk kedua locale (harga tidak dikonversi otomatis ke USD) — kecuali ditentukan lain di `CONTENT.md`.
